## 1. 产品定位与目标

### 1.1 产品定位

为金融机构员工提供统一的内部智能工作平台。员工在有权限的资料和业务数据范围内，使用经过发布审核的助手完成制度查询、投研资料分析和运营异常梳理，获得可核对来源、可编辑、可审阅的内部材料。

平台的价值是缩短找资料、核事实、整理草稿和交接审阅的时间，并让业务负责人能够追溯材料依据、使用范围和人工决定。任务数量、模型调用量或回答长度本身不代表业务收益。

### 1.2 业务问题与目标结果

| 当前问题 | 产品需要改变的体验 | 成功证据 |
|---|---|---|
| 制度分散、版本难辨，员工反复咨询 | 从一个入口提问，回答带适用范围、日期和原文位置 | 正确引用、无答案处理、员工完成时长 |
| 研报与数据需要手工整理，口径容易混淆 | 一次明确标的、期间和口径，收到事实、计算与推断分开的草稿 | 指标核对结果、专家评分、有效采纳率 |
| 运营异常需要多次查询和人工拼接 | 将获准的只读查询组织成异常说明、核对清单与处理草稿 | 人工核对时长、返工量、建议可验证比例 |
| 助手配置与结果缺少版本和责任人 | 应用发布、资料版本、任务结果及审阅记录可对应到具体责任与依据 | 发布记录完整率、审计抽样通过率 |
| 资料撤权后，旧会话和导出仍可能暴露信息 | 权限变化同时影响检索、历史材料、引用和后续下载 | 撤权、删除与历史访问演练 |

### 1.3 已确认约束与本稿建议

| 类型 | 内容 | 对产品的影响 |
|---|---|---|
| 已确认 | 金融机构私有化部署；首批服务内部知识、投研和运营辅助 | 工作台面向内部员工，使用企业身份和资料授权 |
| 已确认 | 优先使用 Deep Agents，并由平台控制权限、预算与发布 | 用户看到受控的任务计划和进度，不能任意增加权限或执行能力 |
| 已确认 | 接入第三方模型；大文件可以使用 OSS | 用户选业务助手和数据范围；供应商、存储路径和密钥由管理配置负责 |
| 已确认 | 没有购买 LangSmith Enterprise；不自建 Agent 可观测体系 | 调试与评测按实际可用的 LangSmith 能力开展，不把未采购能力设为必需依赖 |
| 继承设计 | 首期只读与内部草稿，单域、单数据源、单制度问答模板先验证 | 分阶段开放模板；不因为功能完成就扩大数据范围 |
| 本稿建议 | 页面划分、输入上限、测量样本、性能和业务收益目标 | 用于评审与排期；正式实施前按责任人签定，不能作为已承诺 SLA |
| 待冻结 | 出网模式、批准数据、供应商处理范围、保留期限、容量和实名责任人 | 未冻结时只处理合成数据或已批准低敏数据，不默认允许生产数据外发 |

私有部署描述平台运行位置，不代表模型和调试数据必然留在机构内部。管理端必须明确每个场景可处理的数据等级与允许外部处理的范围；用户确认提示不能代替机构批准。

## 2. 范围、阶段与优先级

### 2.1 阶段定义

| 阶段 | 对外交付范围 | 数据边界 | 退出条件 |
|---|---|---|---|
| S0 需求与治理冻结 | 角色、首个制度域、数据源、供应商、验收基线 | 合成或已批准低敏数据 | 第 17 节关键决策有负责人、证据和签署 |
| S1 单模板验证 | 单制度域、单数据源的制度助手，以及完成它所需的管理、审阅、审计能力 | 合成或已批准低敏数据 | 引用、撤权、删除、任务恢复、审计纵向验收通过 |
| S2 只读扩展 | 增加一个投研模板、一个运营草稿模板 | 仍受批准的数据清单限制 | 三场景分别通过质量、口径、权限和成本门禁 |
| S3 生产准入 | 在批准的用户和数据范围内灰度使用 S1/S2 能力 | 联合批准的生产数据范围 | 业务、数据、风险、安全、运维联合签署，恢复与回滚验证完成 |
| S4 后续能力 | 定时任务、跨空间受控分享、更多数据源；写动作另立需求 | 每项扩展单独授权 | 对应需求、风险与验收完整；不继承首期的默认开放资格 |

S1 是首个可验收交付；S1 与 S2 共同构成首期功能范围。阶段不等同于固定周数，实际排期需在依赖确认和纵向验证后估算。

### 2.2 需求优先级

本文 P0 表示对应阶段上线必须具备，P1 表示可在同阶段验证后优化，P2 表示后续候选。P0 不表示所有阶段同时实施。未标注优化项的安全边界均是适用阶段的阻断要求。

| 能力 | 首期范围 | 后续范围或排除项 |
|---|---|---|
| 员工工作台 | 应用目录、对话、附件、任务、引用、草稿、审阅、导出、反馈 | 移动端原生应用、外部客户门户暂不做 |
| 平台管理 | 空间与角色、模板与版本、知识源、模型/工具目录、额度、发布、审计查询 | 开放工具市场、用户任意代码、通用可视化编排器暂不做 |
| 任务执行 | 可查询进度、等待补充、取消、恢复、失败重试入口 | 定时任务在 S4 另行定义时区、失约与补跑规则 |
| 数据与模型 | 受控资料检索、S2 指标计算与业务只读查询、已批准第三方模型 | 无批准内部模型时，不开放只能内部处理的数据 |
| 观测与审计 | LangSmith 现有能力入口、评测证据关联、独立业务审计 | 不建设 Trace 查询平台、模型链路看板或替代 LangSmith 的评测平台 |
| 业务执行 | 只读查询、生成内部材料 | 不下单、不改账、不授信、不创建真实工单、不发邮件/消息或触达客户 |

内部审阅通过只代表材料在指定范围内可用，不代表对外发布获批，也不会自动触发业务系统写操作。

## 3. 用户、组织与权限

### 3.1 组织概念

机构是法人和合同边界，工作空间是机构内部业务域和资料授权边界。员工可以加入多个空间，但一次任务只能属于一个空间；切换空间不会迁移已有任务。空间成员资格、任务访问资格和源资料权限必须同时满足。

任务是一次有明确目标的执行过程；对话可以包含多个任务。材料是任务产生的可编辑成果，一个任务可以有多个材料修订版。应用是员工可选择的业务助手；应用模板定义输入、产物、资料范围和审阅规则，发布版本固定一次任务采用的具体规则。

### 3.2 角色与职责

| 角色 | 核心目标 | 可以做 | 不能默认做 |
|---|---|---|---|
| 员工/分析人员 | 查制度、整理材料、处理异常 | 发起获准任务，查看本人或明确获授任务，编辑草稿、提交审阅 | 读整个空间的所有任务、修改模型路由、查看他人业务正文 |
| 业务审阅人 | 核对材料和适用范围 | 查看被分配且有资料权限的材料，评论、通过、退回 | 审批自己的材料、改变源资料权限、自动代表机构对外发布 |
| 空间负责人 | 管理业务使用范围和额度 | 管理成员申请、模板可见范围、额度申请和使用统计 | 通过成员管理绕过源系统权限、默认阅读成员正文 |
| 模板维护人 | 提供稳定的业务助手 | 配置草稿模板，提交测试与发布申请 | 自己绕过发布审批或改写已发布版本 |
| 发布人 | 控制上线版本与影响范围 | 核验评测与批准证据，灰度、停用和回滚 | 单人批准自己的变更、临时扩大资料处理权限 |
| 数据所有者/知识管理员 | 管理资料可信度与使用范围 | 确认资料许可与日期、同步、撤回、查询删除进度 | 以索引配置扩大源资料权限 |
| 平台管理员 | 保障配置与运行可用 | 管理接入配置、额度、服务状态与工单 | 默认读取业务正文、绕过审阅或直接查看密钥值 |
| 风险/安全/法务负责人 | 确定使用与处理边界 | 批准数据处理规则、保留规则和例外，阻断不合规发布 | 替代业务专家核验专业结论 |
| 审计人员 | 核验行为和证据 | 在授权案件范围内检索记录、获取证据包 | 无范围查询全部材料或修改审计记录 |
| 运维支持人员 | 恢复服务与处理故障 | 查看脱敏状态和错误码，执行获准恢复流程 | 以排障为由获取无限正文权限 |

### 3.3 权限规则（FR-01，P0，S1）

1. 使用企业登录；无空间成员资格时展示申请入口和联系路径，不展示该空间资料、任务名称、数量或摘要。
2. 列表、搜索、引用、预览、审阅、下载都检查当前权限；仅知道链接或任务编号不能获得访问权。
3. 平台管理权限与业务正文权限分别授予；审阅任务的分配不自动授予源资料权限。
4. 首期支持空间内向具名审阅人授予任务访问权，范围取任务授权与当前资料权限的交集；向全空间公开、跨空间分享默认关闭。
5. 离职、角色移除、源资料撤权后，现有会话也不能继续使用已失效的内容。可见提示为“访问权限已变化，请刷新或联系负责人”，不泄露被撤资料名称。
6. 紧急访问必须指定原因、对象、期限和两名不同批准人，到期自动失效并通知审计；首期可复用机构现有流程，不开放单人管理员旁路。

## 4. 信息架构与页面要求

业务界面使用“助手、任务、资料、材料、审阅”等术语。模型、运行图、状态存储和供应商端点只在需要配置或排障的管理界面展示。

| 页面 | 主要内容 | 核心操作 | 无数据或异常表现 |
|---|---|---|---|
| 应用目录 | 名称、适用场景、负责人、允许资料等级、可用状态 | 进入助手、查看使用说明 | 无可用应用时显示联系空间负责人；不暴露无权应用 |
| 助手工作区 | 输入表单、附件、对话、当前任务、证据侧栏 | 提交、补充信息、查看计划、取消 | 缺字段逐项提示；附件未就绪时不能提交 |
| 我的任务 | 场景、创建时间、状态、材料状态、最近更新 | 筛选、继续、打开、复制输入重试 | 空列表显示发起任务入口；错误保留筛选条件 |
| 任务详情 | 目标、输入范围、进度、资料日期、耗时、产物 | 补充、取消、查看失败原因 | 断线提示重连；无可核实总量不显示虚假完成百分比 |
| 材料详情 | 正文、引用、事实/推断标识、修订历史 | 编辑、送审、查看差异、导出 | 自动保存失败显著提示；不能把未保存内容送审 |
| 我的待审 | 标题、申请人、截止时间、材料版本 | 查看证据、评论、通过、退回 | 过期或已被处理显示只读结果，禁用提交 |
| 知识管理 | 数据源、同步状态、资料日期、负责人、问题数 | 重试同步、撤回、查看删除进度 | 失败原因按权限展示，资料未就绪不能用于回答 |
| 模板与发布 | 草稿、发布版本、评测结论、审批记录、灰度范围 | 创建修订、送评、申请发布、停用、回滚 | 缺门禁证据列出具体阻断项 |
| 空间与额度 | 成员、角色、配额、已用/预留/余额 | 申请加入、调整授权、申请额度 | 额度不足给出申请路径，无权用户看不到其他空间成本 |
| 模型与工具管理 | 业务用途、批准范围、负责人、版本、可用状态 | 申请接入、测试、启停 | 供应商不可用时标记受影响应用；不显示密钥明文 |
| 审计检索 | 授权范围内的时间、主体、动作、结果、关联材料 | 筛选、查看证据、导出记录 | 正文受限时只显示允许的事件元数据 |
| 删除与保留任务 | 申请、处理对象类别、进度、保留原因 | 查询、重试失败步骤、获取完成证明 | 法律冻结明确标为“保留中”，不能显示“全部删除” |

分页保持筛选和排序，首期建议每页 20 条，可选 50 条。工作台只展示业务步骤摘要，不展示模型隐藏推理或把原始工具返回作为进度消息。

## 5. 通用任务体验

### 5.1 选择应用与发起任务（FR-02，P0，S1）

前置条件：用户已登录且拥有空间、应用和输入资料权限。应用页展示适用问题、输出样例、允许数据等级、是否需要审阅、单次限制和业务负责人。

提交前显示任务摘要：空间、助手、资料范围、截至日期、附件、预计使用的额度上限和结果用途。用户选择已发布应用；不能输入任意模型地址、工具名称、网络目标或提升数据等级。

必填不完整时不创建任务。提交成功后立即提供任务编号和状态入口；重复点击或网络重试只创建一个任务。同一次提交携带不同内容时提示冲突，不能悄悄覆盖。发起新任务时才解析新发布版本，已有任务保留原版本。

### 5.2 输入、附件与保存（FR-03，P0，S1）

| 项目 | 业务规则 | 建议首期上限与处理 |
|---|---|---|
| 问题/任务描述 | 去除空白后必填，支持中文和多行，不将文本内指令视为权限 | 4,000 字；超限指出剩余可输入量 |
| 截至日期 | 默认今天，用户可选历史日期；时间口径显式展示 | 不接受未来日期进行事实回溯，提示改为历史日期 |
| 附件类型 | S1 支持 PDF、DOCX、TXT；S2 可增加 CSV、XLSX，只提取内容 | 不执行宏、脚本、外部链接；首期不接受压缩包或加密文件 |
| 附件数量/体积 | 上传、检查、解析成功后才参与任务 | 每次最多 5 个、每个 20 MB、总计 50 MB；服务端再次校验 |
| 文件密级与用途 | 继承已知资料密级；用户申报只能触发更严格检查，不能降级 | 超出应用范围则拒绝，并提供获准处理渠道 |
| 文件解析 | 显示上传中、检查中、可用、失败及重试入口 | 失败附件必须删除或明确排除，不能静默忽略后回答 |
| 表格与扫描件 | 保留页码、单位、表头和识别不确定位置 | 无法可靠识别关键值时请求核对，不能猜测数字 |

上述数量与体积是 D-06 待签定建议。上传附件仅用于该任务及其获准派生材料，不自动加入共享知识库。相同文件名不覆盖原对象；删除输入附件与删除任务按第 11 节流程处理。

草稿输入可按空间政策服务端保存；高密级正文不保存在浏览器持久缓存。退出登录清除页面中的正文，重新打开必须登录鉴权。应用需提示未保存状态，不承诺恢复未成功提交的编辑内容。

### 5.3 计划、进度与补充信息（FR-04，P0，S1）

任务详情展示“准备资料、检索证据、分析整理、检查结果”等用户可理解的当前步骤，以及已完成、等待和失败项。计划可能在同一目标与授权范围内调整；出现目标、范围或预算变化时，需要用户确认新任务或新申请。

需要补充标的、时间或口径时，展示具体问题和已有答案；用户补充后继续原任务。补充信息构成新目标或新增未经授权资料时，保存原任务说明并创建关联的新任务。补充前暂停执行，避免空等占用执行资源。

### 5.4 对用户可见的任务状态（FR-05，P0，S1）

| 状态 | 含义 | 用户可做 | 下一步与边界 |
|---|---|---|---|
| 排队中 | 已接收，等待开始 | 查看、取消 | 获得资源后执行；排队超期显示原因 |
| 执行中 | 正在处理获准步骤 | 看进度、请求取消 | 可能等待补充、交付结果或失败 |
| 等待补充 | 缺少用户输入 | 补充、取消 | 原任务在权限仍有效时恢复 |
| 等待审阅 | 任务流程需要人工决定 | 指定人员审阅，申请人可撤回 | 通过后继续；退回或失效按规则处理 |
| 正在确认结果 | 中断后尚不能核实某步骤是否完成 | 查看、联系支持 | 系统核实后更新；禁止显示成功或诱导重复执行 |
| 已完成 | 结果或明确的无答案说明已交付 | 查看、编辑材料、发起新任务 | 不表示材料已审阅通过或可对外使用 |
| 已失败 | 本次任务无法完成 | 看原因、复制获准输入发起新任务 | 不重开原终态；保留关联关系 |
| 已取消 | 未完成步骤停止，已完成动作记录保留 | 查看允许保留的记录 | 取消不等于删除材料或撤销已下载文件 |

“正在取消”是取消请求的处理提示；收到服务端确认前不标记已取消。“等待补充”与“等待审阅”可以对应同一技术等待态，但产品必须显示具体等待对象。材料送审可以发生在任务完成后，其状态与任务状态分别显示。

关闭页面、刷新或断线不会自动取消任务。重连后从已确认进度继续展示，不重复材料或步骤。运行中断后可安全恢复的任务由系统恢复，恢复不了时明确失败原因；用户主动重试创建新任务并保留原任务关联。

### 5.5 异常、取消与通知（FR-06，P0，S1）

用户发起取消后，平台停止尚未开始的步骤并确认执行中的状态。若结果已经交付，提示“任务已完成，可申请删除材料”；不能把成功改写成已取消。费用按已经发生的用量结算，不将取消解释为免费。

站内任务列表和待审列表承担首期通知；需要行动、完成、失败、额度不足和权限变化时显示可见提醒。同一事件不重复提醒；不默认发送邮件、即时消息或客户通知。审阅截止时间展示机构时区，超时不自动通过。

## 6. 制度知识助手

### 6.1 用户目标与输入（FR-07，P0，S1）

员工希望了解某项制度在指定业务范围和日期下的要求，并能够打开依据核对。输入包括问题、制度域、适用主体或岗位（问题存在歧义时补充）、截至日期及可选附件。

例：员工询问“截至指定日期，某类差旅费用需要哪些审批材料”。这是需求示例，不预设任何机构制度或答案。

### 6.2 主流程

~~~mermaid
flowchart LR
    A[选择制度助手并提问] --> B{适用范围明确?}
    B -->|否| C[补充岗位/地区/日期]
    C --> B
    B -->|是| D[查找有权访问且当时有效的资料]
    D --> E{证据是否充分?}
    E -->|是| F[回答并标注逐项依据]
    E -->|否| G[说明缺口或资料冲突]
    F --> H[打开引用核对]
    H --> I[按规则保存或导出内部材料]
~~~

### 6.3 输出和判断规则

| 输出部分 | 必须具备 |
|---|---|
| 直接回答 | 回答问题本身，列清适用条件、操作要求与例外；不得编造审批条件 |
| 引用 | 对应结论、制度标题、版本、适用日期和页码/条款位置；用户点击可定位 |
| 适用范围 | 业务域、适用主体、截至日期；不将其他地区或岗位要求泛化 |
| 不确定或缺口 | 无资料、资料冲突、资料过期、识别不确定的具体影响及下一步 |
| 交付标签 | 内部辅助信息、资料核验时间；需要专业确认时标出责任渠道 |

无足够授权证据时返回“当前可用资料不足以回答”，不声称整个机构不存在此制度，也不暴露其他用户能访问的资料。制度冲突时并列展示有权查看的冲突条款，请求业务核实，不由模型自行确定制度效力。历史查询可引用当时有效而如今失效的资料，但必须显著标明历史用途；当前查询不能把已失效制度当作现行要求。

问答允许经过交付检查的分段展示。未校验引用、权限或敏感内容的文本不得先展示再撤回。普通问答无需每次双人审批；若模板要求审阅，按第 9 节控制相应导出。

## 7. 投研资料分析助手

### 7.1 输入与使用范围（FR-08，P0，S2）

面向研究人员，首个模板建议为“指定标的与期间的资料摘要及财务比较草稿”。输入包括标的的明确身份、业务期间、资料截至日期、比较对象、币种和单位、指标口径、需要回答的问题、可用资料及输出结构。

存在同名主体、期间不一致或币种不明时先澄清。平台不生成交易指令、不直接发布研究报告、不向客户发送材料。未获批处理的敏感研究信息或个人信息必须拒绝进入对应模型路径。

### 7.2 主流程与结果结构

1. 用户确认研究任务摘要，包含比较主体、期间、截至日期和预期成果。
2. 从获准资料和权威指标来源收集事实；遇到数据缺失或口径不一致，展示差异并补充确认。
3. 对金额、同比、环比、收益率等执行可复核计算，保留输入、单位、币种、舍入规则和来源。
4. 生成草稿：任务范围、资料摘要、指标对比、变化解释、风险与反证、资料缺口、参考资料。
5. 研究人员编辑后送审。审阅人核查事实与推断、数字口径、时间和引用，通过后按获准格式导出内部版本。

| 内容类别 | 产品展示要求 | 禁止行为 |
|---|---|---|
| 事实 | 来源和日期可定位 | 把未证实的模型描述写成事实 |
| 计算结果 | 原始数值、计算口径、币种/单位与结果可核对 | 用语言模型估算替代规定计算；将缺失值当零 |
| 分析推断 | 明确标记推断，写出支持证据与限制 | 将推断伪装为确定预测或机构正式观点 |
| 资料缺口 | 缺什么、影响什么、能否继续 | 默默替换主体、期间或换用未来资料 |

“截至某日”以当时可知资料为准。财报对应较早期间但在截至日之后发布，也不能用于当时判断；后续重述资料与当时已知版本分别记录。当前权限始终约束历史回看，保存历史权限快照不能恢复用户已经失去的访问权。

历史可重现指能够核验当时输入、资料、口径、版本与保存的产物，不承诺再次调用模型得到逐字相同文本。无法取得必要历史证据时明确“无法完整核验”，不得标记完全可重现。

## 8. 运营异常分析助手

### 8.1 输入与主流程（FR-09，P0，S2）

运营人员输入异常类型、获准业务编号、发生时间和可选脱敏附件。首个模板由业务确认一种异常，例如对账差异说明；本 PRD 不预设真实业务字段或处理规则。

1. 校验编号所属范围和只读查询权限。
2. 获取相关状态、规则与记录，显示信息时间和不完整项。
3. 对比规则与记录，输出已证实事实、可能原因、待核对项。
4. 生成处理建议和工单草稿，由运营人员编辑、送审或导出。

### 8.2 输出与边界

结果包含异常摘要、查得记录、规则依据、差异明细、候选原因、核对清单、建议负责岗位及工单草稿。每项处理建议关联获准查询结果；不能查询到记录时只说无法获取当前信息，不推断业务操作已经成功或失败。

界面使用“生成工单草稿”，不能显示“已建单”。不提供修改业务状态、冲正、调账、通知客户的按钮；审阅通过也只改变材料状态。复制草稿到现有业务系统由具备权限的人员按原制度执行。

## 9. 材料、引用、审阅与导出

### 9.1 材料管理（FR-10，P0，S1）

每份材料有所有者、空间、来源任务、生成日期、资料截至日期、密级、材料修订版和审阅状态。编辑保存生成新的可追溯修订，不覆盖生成依据；恢复旧稿产生新修订，不抹去中间记录。

多人同时编辑时，后提交者必须看到版本冲突和对比提示，不能覆盖另一人的更新。用户修改含事实或数字的段落后，原引用不自动被视为支持新结论，必须重新核验；引用删除或资料撤回时标记受影响段落。

### 9.2 引用核验（FR-11，P0，S1）

点击引用打开对应版本和具体位置，显示标题、日期、来源与获取时间。扫描件显示原始位置和识别文本；表格显示表头、单位和脚注。引用无法解析时明确失败，不能跳转到相似资料冒充原文。

源资料撤回后，正文中依赖该资料的内容、摘要、引用和导出均需重新评估；删除一个链接不足以解决派生信息泄露。无法安全分离受影响内容时限制整份材料访问，提示申请重新生成。

### 9.3 审阅规则（FR-12，P0，S1）

| 状态 | 申请人操作 | 审阅人操作 | 转换规则 |
|---|---|---|---|
| 编辑中 | 保存、送审 | 无 | 送审固定具体材料修订、证据、适用范围和截止时间 |
| 待审阅 | 查看、撤回；修改需撤回后新建修订 | 评论、通过、退回 | 提交前再次核对身份、资料权限和版本 |
| 已退回 | 查看理由、修改、再次送审 | 查看历史决定 | 原决定保留，新修订重新送审 |
| 已通过 | 查看、按规则导出、创建新修订 | 查看决定与证据 | 修改内容、用途或证据发生关键变化后，原通过不适用于新版本 |
| 已撤回/已过期/已失效 | 更新材料或重新申请 | 只读查看 | 不能继续使用旧审阅链接提交批准 |

申请人与审阅人必须不同；候选审阅人需满足岗位、数据范围和无利益冲突要求。审阅人不能查看必要证据时不能批准，应请求负责人重新分配或走正式授权流程。委派限定在合格人员范围，记录原人、接收人和理由，不转让已失效权限。

通过、退回都记录人、时间、意见和所审版本，退回理由必填。建议审阅期限为 2 个工作日，但应由 D-07 确定机构日历和模板规则；超时只提醒并失效，不自动通过。重复提交只产生一次决定；两人并发处理时，后提交者看到已处理状态。

### 9.4 导出（FR-13，P0，S1；扩展格式 S2）

S1 建议支持 PDF 内部材料和引用清单；S2 按模板增加 DOCX 草稿和经检查的 XLSX 对比表。格式为本稿建议，冻结于 D-06。审阅要求由模板决定：普通问答可导出带“未审阅”标识的内部材料；需审阅的投研或运营材料在通过前禁止正式版本导出。

每次导出重新核验访问、资料有效性、材料修订和审阅状态。文件包含内部用途、密级、导出人、时间、材料版本和必要水印；文件名不含客户账号等敏感标识。材料与引用中的不确定说明必须一起导出，不允许删除风险提示后仍标记为已审阅。

下载链接短时有效且不可充当可转发的永久访问凭证；要求源权限撤销后立即阻止新下载的场景必须使用受鉴权下载通道。无法即时撤销的直接签名链接不能用于该类资料。下载成功不代表已经阅读；失败重试不能重复生成冲突的材料版本。

平台可以阻止后续访问并向已知下载人发出撤回通知，但无法保证删除已下载到终端的副本；高密级资料可禁止下载，终端处置依赖机构已有管控。表格公式注入、预览脚本、外链和恶意内容检查必须在交付前完成。

### 9.5 反馈（FR-14，P1，S1）

员工可标记有帮助/无帮助，选择引用错误、制度过期、数字错误、答非所问、权限问题等原因，并定位具体段落。反馈关联任务和材料版本，新增敏感文本按资料规则处理。

反馈状态为待分派、处理中、已处理或不采纳并说明原因。明确泄露或越权反馈按事件流程及时限制受影响应用。样本纳入评测须先审核、脱敏与授权；用户点击反馈不等于同意向第三方发送正文，不自动修改生产模板或进行训练。

## 10. 管理与发布能力

### 10.1 空间与成员（FR-15，P0，S1）

空间需配置业务负责人、数据所有者、允许应用、资料范围、成员角色、额度、数据处理规则和停用责任人。缺少负责人或处理范围不得启用。成员新增、角色变更、移除均记录申请、执行者与生效时间。

停用空间立即阻止新任务，并根据安全原因暂停或终止已有任务；普通维护停用可排空获准任务。受保留规则约束的历史记录继续由授权角色查看，不能以停用为由清空审计证据。

### 10.2 模板配置（FR-16，P0，S1）

模板必须配置：名称、用途、业务负责人、输入字段、适用用户、知识和指标范围、输出结构、引用要求、审阅规则、导出格式、已批准模型/工具、额度、最长处理时间、失败提示与有效期。

草稿→待评测→待审批→已发布→停用构成可见发布流程。编辑已发布配置创建新版本；试运行限定测试空间和获准样本，不能直接用生产正文进行调试。复杂编排由研发维护，业务管理员不上传生产代码或任意工具。

### 10.3 评测、灰度、回滚（FR-17，P0，S1）

发布申请包含候选版本、变更说明、受影响用户与资料、固定测试集版本、各项评测结果、已知限制、灰度范围、停用人和回滚目标。评测在已获准的 LangSmith 能力和机构验证流程中完成，管理端只登记结果摘要和证据引用，不自建实验分析产品。

业务负责人确认答案与流程，数据所有者确认资料范围，安全/风险确认处理边界，发布人核验完整性。模板维护人不能独立批准自己的版本。未通过硬门禁、证据缺失或过期时禁止发布；新增供应商或密级不是普通模板编辑。

灰度限定明确用户或空间。回滚只改变新任务使用的版本，历史任务保留原依据；普通更新允许旧任务按原规则结束。若原因是权限、安全或供应商资格失效，则受影响在途任务也须停止或重新核验，不能以固定版本为由继续违规处理。

### 10.4 模型与工具目录（FR-18，P0，S1；指标工具 S2）

管理端显示每个服务的用途、负责人、处理数据等级、供应商与处理地区、批准有效期、版本、额度、是否只读、停用状态及依赖应用。接入申请需涵盖生成、向量处理、重排、OCR 和评测等所有可能处理内容的阶段。

第三方服务异常时只能使用预先批准、具备相同数据资格并通过模板评测的备用服务；没有合格备用就提示暂停或失败。不能为完成任务静默切换到未批准供应商。员工无需选择供应商，也不能通过输入指令打开联网或 Shell 能力。

### 10.5 额度与成本（FR-19，P0，S1）

额度按机构、空间、用户/模板和任务控制，可设置月度金额、任务并发和单次使用上限。管理员可见“已发生、执行中预留、可用余额”，员工可见本人任务上限与额度不足原因。

并发任务也不得突破共享额度。达到上限阻止新步骤或新任务，已发生使用照常记录；重试和子任务合并计入同一任务预算。额度加批记录审批人和理由，不能隐式提高单次上限。

统计模型、工具、文件处理和平台可归集费用；暂不可获得的供应商费用显示“待结算/估算”，注明范围与币种，不显示为零。业务成本报表用于配额和价值管理，不扩建成 Agent Trace 系统。

## 11. 知识、数据与保留

### 11.1 资料生命周期（FR-20，P0，S1）

资料状态为待接入、检查中、解析中、待确认、可用、更新中、不可用/撤回。知识管理员可以查看失败原因、重试进度和负责人；没有批准权限、日期或许可范围的资料不能进入可用集合。

资料至少包含来源、版本、所属空间、所有者、密级、使用许可、适用范围、发布日期、生效/失效日期、采集时间和最后授权核验时间。缺少历史可知时间的资料不得用于宣称严格历史回溯的回答。新版本不覆盖旧版本；旧版本是否可业务访问取决于当前权限、时间用途和保留规则。

权限同步失败或超过批准的新鲜度窗口时暂停受影响资料服务，不继续使用过时授权。内容更新失败不自动将旧内容标为当前；若政策允许在指定时限使用旧资料，回答须明确数据截止时间，现行制度效力不明时应停止给出确定结论。

### 11.2 撤权、撤回与删除（FR-21，P0，S1）

撤权改变谁可以访问，撤回改变资料是否可用于业务，删除处理保留副本；三者必须在界面上区分。用户发起删除时显示申请对象与可能保留类别；源资料删除由数据所有者处理，普通用户不能删除全机构共享源。

处理流程：登记申请→限制业务访问→识别受影响资料与材料→处理检索副本和历史上下文→处理文件、评测和调试副本→按规则处理归档/备份→生成处理证明。单步失败可重试，界面显示未完成类别、原因、责任人和下一步。

状态为处理中、部分完成、等待保留期、法律冻结、完成或处理失败。“业务访问已阻止”与“物理副本已删除”分别显示；存在保留对象时不能标记无条件全部删除。备份恢复后必须重新应用撤回和删除清单，不能恢复可访问的已删除资料。

### 11.3 保留矩阵（FR-22，P0，S1）

| 对象类别 | 业务访问角色 | 触发处理的事件 | 保留/删除原则 | 责任方 |
|---|---|---|---|---|
| 原文、附件、解析副本 | 当前获准使用者、数据管理人员 | 源撤回、许可到期、用户申请 | 原文和副本协同处理；保留期由 D-04 签定 | 数据所有者 |
| 检索索引与向量 | 服务使用，人员无默认直接读取权 | 权限/内容变化、源删除 | 不作为规避撤权的独立资料库 | 数据平台 |
| 对话、运行保存状态、摘要 | 获准任务参与人 | 任务删除、源撤权、期限到期 | 影响派生内容时限制访问并清理 | 平台与数据所有者 |
| 草稿、审阅材料、导出对象 | 获准作者、审阅人、证据访问人 | 材料撤回、源删除、期限到期 | 审阅记录和正文分别处理；终端副本遵从机构制度 | 业务负责人 |
| LangSmith 调试与评测数据 | 单独获准的调试/评测人员 | 期限到期、授权撤回 | 按批准数据和实际账户能力处理；无法满足要求则不发送对应数据 | 平台与安全负责人 |
| 业务审计 | 有范围授权的审计人员 | 保留期到期、法律冻结解除 | 不可随意修改；冻结期间保留并限制访问 | 审计/法务 |
| 备份与归档 | 获准恢复人员 | 生命周期到期、删除申请 | 限制恢复与访问，记录待到期副本及证明 | 运维 |

本 PRD 不虚构法定保留年限。每一类必须在试点批准前填写明确期限、触发条件、法律冻结依据和责任人；空白不能默认永久保存。OSS 保存原文和大对象、数据库保存业务状态属于已定实现约束，员工不选择底层介质。

## 12. 审计、支持与 LangSmith 使用边界

### 12.1 审计需求（FR-23，P0，S1）

必须记录登录与关键访问、任务发起、权限决定、资料引用、只读工具使用、模型版本、材料修订、审阅、导出、发布、停用、权限变化、删除、人工接管和结果不确定事件。记录可回答“谁在何时、为何、在什么范围内、依据什么版本、做了什么、结果怎样”。

审计人员可按时间、空间、获准主体、动作、结果和关联任务检索；证据包包含相关版本、引用、人工决定、完整性校验结果和缺失说明。审计查询与导出行为本身也记录；审计管理员不能删改证据以掩盖操作。

正文与事件元数据分别授权和保留。关键审计记录无法可靠保存时，不允许继续发布、导出、批准或开启新的受控访问；已有任务转为暂停或失败并清晰告知，不能先执行后丢失证据。

### 12.2 LangSmith 与故障支持（FR-24，P0，S1）

Agent 调试和评测使用 LangSmith，平台最多提供已授权项目的入口及任务关联标识，不复制建设调用树、链路检索、实验管理或监控大盘。独立业务审计、任务进度和额度统计是本产品必要能力，不能作为自建 Agent 可观测体系的扩张入口。

使用前由负责人核验实际账户功能、人员权限、额度、驻留和删除能力；本 PRD 不假设具体套餐已经具备任何企业能力。默认只允许经批准的脱敏元数据，原始问题、附件、检索正文、工具完整结果、账户标识、密钥和隐藏推理不得发送。

| 情况 | 用户/管理端表现 | 产品处理 |
|---|---|---|
| LangSmith 可用且发送范围获批 | 授权人员可打开对应入口 | 按批准字段与额度采集，不因方便排障扩大范围 |
| 套餐/驻留/删除要求不满足 | 管理端显示“调试采集未启用”及原因 | 关闭相应采集；不搭建本地替代 Trace 平台 |
| 调试采集短时故障 | 管理端标注证据缺口，员工仍看到业务任务状态 | 若已批准允许缺少 Trace 且业务审计正常，可继续；否则暂停相关能力 |
| 新版本缺少必要评测证据 | 发布页显示门禁未通过 | 保持候选版本未发布；不能绕过门禁或伪造通过 |
| 业务审计故障 | 显示任务受限及处理路径 | 按 FR-23 阻止不能留证的操作 |

完全隔离模式下不能默认启用 LangSmith Cloud 或第三方模型。在没有批准内部能力且不能出网的情况下，对应助手应不可用；允许继续做合成数据演示的决定也须明确环境。底层服务健康与值班复用机构现有工具，不新增第二套 Agent 观测产品。

## 13. 体验、可靠性与安全验收要求

### 13.1 异常交互矩阵

| 触发条件 | 用户提示/行为 | 可恢复路径 |
|---|---|---|
| 无权限或权限被撤销 | 不展示敏感标题和正文，说明访问条件变化 | 刷新、走正式申请；不沿用旧缓存 |
| 没有足够证据 | 说明资料缺口，不编造答案 | 缩小问题、补充获准资料或人工咨询 |
| 模型超时或限流 | 显示等待/失败及是否已经接收任务 | 有界自动恢复；不可恢复时关联新任务重试 |
| 解析失败 | 定位到获准附件，说明格式或质量问题 | 替换文件或明确排除后提交 |
| 预算不足或超时 | 停止新步骤，说明消耗及上限 | 申请额度，重新发起；已产生片段标为未完成 |
| 部分证据撤回 | 限制受影响材料，取消旧审阅有效性 | 在当前权限下重新生成、重新送审 |
| 审阅版本冲突 | 显示所审版本已变化 | 刷新并重新核对，不能沿用旧决定 |
| 网络断开 | 显示重连中，不重复创建任务 | 恢复任务列表与已确认进度 |
| 下载失效 | 显示需重新校验访问 | 重新申请下载，不能无限延长旧链接 |
| 无法确认处理结果 | 显示待确认和负责人路径 | 系统核验或人工接管，避免盲目重复 |

用户错误信息不包含供应商密钥、内部地址、完整异常栈或其他空间信息；提供可用于支持定位的关联编号。无障碍要求包括键盘可操作、焦点明确、状态不只靠颜色表达、表单错误定位和长文引用可访问。

### 13.2 性能与恢复候选目标（NFR-01）

以下全部为待签定验收候选值，不是容量承诺。依赖模型和知识服务的失败计入端到端结果，不通过排除依赖故障改善统计。

| 指标 | 候选目标 | 测量口径 |
|---|---|---|
| 任务接收 | P95 ≤ 2 秒 | 从有效提交到收到唯一任务编号，包含鉴权和接收排队 |
| 普通知识问答完成 | P95 ≤ 20 秒 | 从有效提交到完成检查的结果交付，含执行排队；人工补充另计 |
| 普通任务状态查询 | P95 ≤ 2 秒 | 登录有效且网络处于约定范围内的可见状态更新 |
| 月度可用性 | 99.9% 候选 | 约定服务窗口内，合格请求能接收并完成承诺功能的比例；窗口与排除项需签定 |
| 恢复能力 | RPO ≤ 15 分钟、RTO ≤ 4 小时作为讨论值 | 基于业务影响分析和演练；关键审计/批准记录需独立确认是否允许数据损失 |
| 权限撤销传播 | 60 秒内阻止受影响的新检索、预览、模型输入和下载作为候选 | 从权威撤销事件提交计时；无法核验授权新鲜度时暂停访问 |

复杂投研与运营材料以异步方式处理，不套用 20 秒问答目标。总时限和步骤预算由模板明确，暂停人工等待与执行时限分别计量。已送到批准供应商的内容无法靠撤权召回，因此还需供应商保留与删除机制，而不是只测试前端撤权。

负载单至少记录同时在线与实际并发、请求到达分布、场景比例、资料与附件大小、输出长度、缓存条件、模型路由和测试时间。未签定这些条件，不对外发布 SLA，也不据此购买固定规模资源。

### 13.3 安全与交付要求（NFR-02）

跨空间、角色越权、源资料撤权、提示注入、恶意附件、前端脚本注入、表格公式注入、数据外发和运行资源超限均须有阻断用例。输入、文档和工具内容中的“忽略规则、读取密钥、调用其他工具”等文本只能作为内容，不能改变平台权限。

任务文件和子任务隔离，共享总预算且不得提升身份；普通员工界面不开放 Shell、数据库连接、任意网址或永久记忆开关。长期共享记忆不属于首期，聊天内容不得自动成为其他员工的知识来源。

### 14.3 质量样本与候选阈值

下面给出可直接讨论的候选验收方案，D-08 必须在运行最终测试集前签定，避免按结果事后改阈值。测试用例必须由业务专家标注，模型评分可辅助但不能作为数字、权限和制度效力的唯一裁判。

| 维度 | 候选样本与切片 | 候选通过标准 |
|---|---|---|
| 制度问答 | 至少 300 个问题，现行、历史、无答案、冲突、表格/OCR 各至少 40 个 | 需要证据的结论中引用支持率 ≥ 98%；引用可定位率 100%；专家判定任务完成率 ≥ 90% |
| 制度边界 | 上述现行、历史和冲突切片单独统计 | 不出现把失效制度当作现行、不适用主体误套、未来资料误用；任一可复现问题阻断 |
| 无答案处理 | 独立统计无答案切片及应答切片 | 无答案正确处理率 ≥ 95%，并报告可答问题误拒答率；不能通过全部拒答达标 |
| 投研 | 至少 100 个任务，覆盖币种、单位、期间、舍入、缺失值和历史日期；另设至少 200 个固定计算样例 | 关键计算按签定精度全部通过；任务专家合格率 ≥ 90%；事实/推断不混淆 |
| 运营 | 至少 100 个异常样例，正常、缺记录、规则冲突、过期数据分别覆盖 | 关键业务事实全部可核对；专家合格率 ≥ 90%；业务写入和对外触达为零 |
| 权限与安全 | 至少 200 个攻击与撤权样例，覆盖所有交付入口及受控模型阶段 | 可复现越权、泄露、任意执行和未经批准外发为零；出现一个即阻断 |
| 恢复与删除 | AC-05/06/10/13 所有故障注入点，各至少重复 3 次 | 状态、访问限制和证据均符合预期，无重复交付或假删除证明 |

比例同时报告分子、分母、95% Wilson 置信区间及各切片结果；按任务抽样的多条结论具有相关性，引用率的置信区间需按任务聚类重采样，不能把每条引用当独立样本。上述非安全比例以点估计达标作为本稿候选规则；安全和关键正确性使用零已知失败的阻断规则。有限样本零失败不证明风险为零，生产仍需抽检和事件响应。

### 14.4 发布阻断与回滚

出现越权泄露、未批准外发、关键金额错误、历史查询使用未来资料、现行制度误用、审阅绕过、结果不确定却标成功、审计证据缺失或关键删除失效，立即阻断发布并停止受影响扩展。上线后复现同类问题时，先限制相关模板与数据范围，再修复和复测；业务负责人不能以采纳率高豁免硬门禁。

| 节省处理时长 | 同类人工流程时间减去平台辅助后的人工输入、核验、修改和审阅时间 | S2 候选中位数减少 ≥ 20%，待 D-08 签定 |
| 返工率 | 因事实、口径或流程错误需要重新处理的材料 / 已交付材料 | 与人工基线比较；单独统计严重错误 |
| 每个有效任务成本 | 可归集模型/工具/处理/评测等费用加必要人工复核成本 / 有效完成任务数 | 明示未计入的基础设施与固定费用，不以单次 Token 费用替代 |
| 活跃与留存 | 授权人群中实际完成任务的人数，按部门与场景聚合 | 观察是否解决真实需求，不用于个人绩效排名 |

建议每场景至少 30 组同难度配对任务比较人工与平台流程，记录参与者经验和核验时间，避免把熟练程度差异当作平台收益。首期不提供员工行为排行榜，不采集无必要的正文埋点；汇总数据仍遵守空间与人员范围权限。

### 16.2 职责分工

产品负责人维护需求范围和取舍；业务负责人对答案、流程与价值验收负责；数据所有者对源权限、许可和有效性负责；风险/安全/法务负责数据处理和记录规则；研发对实现与恢复证据负责；测试负责独立验证与需求覆盖；运维负责容量、演练和事件处置；发布人核对全部批准和回滚能力。

每项职责要填入姓名或机构岗位的实际持有人，并有替补及升级路径。本文件没有任何人已批准的默认含义。存在供应商采购、数据授权、指标定义或法务依赖时，记录负责人和最晚决策点后再估工，不沿用原蓝图的固定周数作为承诺。
